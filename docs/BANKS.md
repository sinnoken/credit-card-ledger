# 各銀行帳單格式

每家銀行的辨識方式與解析要點。座標單位是 PDF 點（pt），原點在左上。銀行改版時，核對會先報「不符」或「找不到…（可能改版）」，再回來這裡對照、更新 `web/src/banks.js`。

## 共通規則

- 民國年 + 1911 = 西元年；日期一律用 `YYYY-MM-DD` 字串，不用時區。
- 「上期應繳」「小計」「本期應繳」等總額列不輸出，只拿來核對。
- 繳款、自動扣繳列不輸出，但計入核對。
- 回饋、刷卡金、折抵為負數，類型跟原消費或卡片預設。

## 繳款截止日

只是參考資訊：找不到就留空，不會讓帳單解析失敗，也不會擋匯出。有一半的銀行只能靠位置抓，所以抓到的日期必須落在結帳日後 7–35 天內（實際是 14–18 天），否則丟棄。本期應繳 ≤ 0 時，銀行印的是「無需繳款」而不是日期；畫面和「核對結果」直接依本期應繳顯示「無需繳款」，不解析那幾個字。

| 銀行 | 位置 |
| --- | --- |
| 台北富邦 | 「繳款截止日」標籤正下方（和結帳日同一行） |
| 中國信託 | 第 1 頁 x 180–300 的第一個完整日期（標籤讀不到） |
| 兆豐 | 「上期待繳總額…繳款截止日」表頭下一行的最後一格 |
| 台新 | 開頭是「繳款截止日」的那一行，最後一格 |

## 合作金庫的數字 0

這家的字型在 pdf.js 裡以位元組顛倒的方式解碼（U+3100 其實是 `1`），而數字 0 會變成全形空白，或被併進很寬的空白項目裡而消失。`core.js` 會：

1. 把顛倒的字碼轉回來。
2. 從頁面的繪圖指令找出每個 0 實際畫在哪裡，補回對應的位置。
3. 找不到任何 0 的位置、但頁面上有數字時，改用舊的寬度判斷，並讓帳單帶「合庫的 0 無法辨識，請人工核對」警告。

程式不會用固定距離去推算少了幾個 0，因為那樣可能把金額放大 10 倍，而核對仍會通過。

## OCR

- 只截說明欄那一格，以 300 dpi 渲染，再裁到單行文字的墨跡範圍；每格用兩種邊界各辨識一次，取較長的結果。
- 模型是 PP-OCRv3 中文辨識模型（ONNX），以 onnxruntime-web 單執行緒 WASM 執行。
- 常見錯字（簡體字、`一`／`－`）用設定裡的 OCR 修正表處理；再與學到的摘要比對（相似度 ≥ 0.85 時改用既有寫法）。
