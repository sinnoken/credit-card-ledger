# 架構

金額只從 PDF 文字層取得，每份帳單核對通過才能直接匯出；OCR 只用來補說明欄。全部在瀏覽器執行，沒有後端。

## 資料流

```
PDF 與密碼 → 讀取（pdf.js） → 銀行解析器 → OCR（只中信、合庫） → 分類器 → 審核表 → 匯出
                                  │                                ↑           │
                                  └──────→ 核對 ───────────────────┼──→ 審核表 │
                                                                   設定 ←──────┘（你的修正）
```

| 模組 | 檔案 | 職責 |
| --- | --- | --- |
| 讀取 | `web/src/core.js` | 用密碼開檔、取文字與座標、合成行與欄位片段、修正字碼顛倒的字型、補回被吃掉的 0 |
| 銀行解析器 | `web/src/banks.js` | 判斷銀行、切出明細、取結帳日與上期／本期總額；每家一個函式 |
| OCR | `web/src/ocr.js` | 只截說明欄那一小塊，用 PP-OCRv3 辨識；模型快取在 IndexedDB |
| 分類器、核對 | `web/src/classify.js` | 剔除繳款列、分類、決定工作表、核對金額 |
| 設定 | `web/src/settings.js` | 卡片名稱、規則、學到的「摘要 → 類型」；存在瀏覽器，可匯出匯入 JSON |
| 匯出 | `web/src/export.js` | ExcelJS 產生 .xlsx；複製用的 TSV |
| 介面 | `web/src/app.js`、`template.html`、`styles.css` | 放入 → 確認 → 匯出，以及設定抽屜 |

`web/build.py` 把以上檔案內嵌成單一的 `dist/index.html`。

## 正確性

1. **核對**：每份帳單所有明細（含繳款）合計 ＝ 本期應繳 − 上期應繳，否則標「不符」並排在最上面。
2. **匯出關卡**：有不符、需核對或「需人工確認」的列時，要勾「我知道，仍要匯出」；之後只要出現新問題，這個勾選就會自動取消。
3. **警告而不猜**：解析時遇到無法確定的情況（例如合作金庫的 0 無法辨識），帳單會帶「需核對」警告，不會自行調整金額。
4. **參考實作**：`python/convert.py` 是最早驗證過的版本；JS 版用同一批帳單逐筆比對它的輸出。

## 分類順序

1. 國外交易手續費 → 跟前一筆消費同類型；「折抵_XXX」→ 跟 XXX 同類型
2. 關鍵字規則
3. 學到的「摘要 → 類型」（來源：匯入的活頁簿，或你按「套用到同摘要」）；手動學到的不會被活頁簿蓋掉
4. 卡片預設類型，標黃

## 隱私

- PDF、密碼、明細只存在分頁的記憶體裡，關掉分頁就消失。
- 設定存在瀏覽器的 localStorage，不含金額和密碼。
- 頁面只從固定的 CDN 載入 pdf.js、onnxruntime-web、ExcelJS；OCR 模型和 WASM 跟著頁面一起發佈。
